## 〇、UI 页面 → 数据表映射

> 已实现的 12 个页面与数据表的对应关系，方便前后端联调时定位。
> ✅ = 后端 API 已实现，⏳ = 待实现。

| 页面 / Kotlin 文件 | 涉及的表 | 核心查询 | 后端 API |
|-------------------|---------|---------|----------|
| **LoginScreen** / **RegisterScreen** | `users` | `INSERT INTO users` / `SELECT WHERE username` | ✅ `POST /api/auth/register` `/api/auth/login` |
| **HomeScreen** (手势匹配) | `emojis` `tags` `emoji_tags` | MediaPipe 端侧提取 22 维特征 → `POST /api/match/gesture` 后端 KNN → 返回匹配 emoji；标签→`JOIN emoji_tags + tags` | ✅ |
| **CommunityScreen** (社区广场) | `emojis` `likes` `comments` `favorites` | `SELECT * FROM emojis WHERE source_type=2 ORDER BY created_at DESC` (双列瀑布流)，点赞数/评论数冗余在 `emojis` 表 | ⏳ |
| **RankingScreen** (排行榜) | `emojis` `likes` | `SELECT * FROM emojis ORDER BY like_count DESC` + 时间过滤（24h / 7d） | ⏳ |
| **TopicChallengeScreen** (话题挑战) | `topics` `topic_submissions` `emojis` | 今日话题 `WHERE status=1 AND NOW() BETWEEN start_time AND end_time`；投稿 `INSERT topic_submissions` | ⏳ |
| **BountyScreen** (表情包悬赏) | `bounties` `bounty_submissions` `users` | `INSERT bounties` 发布；`INSERT bounty_submissions` 投稿；`UPDATE bounties SET status=1` 采纳 | ⏳ |
| **BattleScreen** (房间大厅) | `danmaku_rooms` | `SELECT * FROM danmaku_rooms WHERE status=1` | ⏳ |
| **BattleRoomScreen** (弹幕房间) | `danmaku_rooms` (消息不持久化，Redis/内存缓存最近20条) | WebSocket 推送，无需查库 | ⏳ |
| **ImitationContestScreen** (模仿大赛) | `game_matches` `game_participants` `emojis` | `SELECT target_emoji_id` 随机选题；`INSERT game_participants` 存分数 | ⏳ |
| **ProfileScreen** (个人中心) | `users` `emojis` `favorites` `search_history` `follows` | `SELECT COUNT(*) FROM emojis WHERE uploader_id`；`SELECT * FROM favorites WHERE user_id`；`SELECT * FROM follows` | ⏳ |
| **FollowScreen** (好友关注) | `follows` `users` | `SELECT * FROM follows WHERE follower_id` / `WHERE following_id` JOIN users | ⏳ |

### Kotlin 数据模型 ↔ 数据库字段对照

**`MemeItem.kt` → `emojis` 表：**

```kotlin
MemeItem(
    id            → emojis.id
    imageUrl      → emojis.file_url
    thumbnailUrl  → emojis.thumbnail_url       ← ⚠️ 建议新增字段
    title         → emojis.description
    author        → users.nickname             (JOIN users ON uploader_id)
    authorAvatar  → users.avatar_url           (JOIN users)
    tags          → tags.name                  (JOIN emoji_tags + tags)
    likeCount     → emojis.like_count
    commentCount  → emojis.comment_count       ← ⚠️ 建议新增冗余字段
    isLiked       → likes 表是否存在(user_id, emoji_id)
    isCollected   → favorites 表是否存在(user_id, emoji_id)
    createdAt     → emojis.created_at
    source        → emojis.source_type         (映射: 0→library, 1→library, 2→community)
)
```

**`User.kt` → `users` 表：**

```kotlin
User(
    id             → users.id
    username       → users.username
    nickname       → users.nickname
    avatar         → users.avatar_url
    bio            → users.bio
    memeCount      → SELECT COUNT(*) FROM emojis WHERE uploader_id   (即时查询)
    followerCount  → users.follower_count
    followingCount → users.following_count
    token          → JWT (不存库，由后端签发)
)
```

```
  │               ├──N:M──→ tags (via emoji_tags)
  │               │

  ├──N:M──→ users (via follows)                        关注

topics ──1:N──→ topic_submissions

```

## 三、表情包核心

### 3.1 emojis（表情包表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PK AUTO_INCREMENT | 表情包 ID |
| `file_url` | VARCHAR(512) | NOT NULL | 原图存储路径（MinIO / 本地） |
| `thumbnail_url` | VARCHAR(512) | - | ⚠️ 缩略图路径（建议新增，瀑布流加载用） |
| `file_md5` | VARCHAR(32) | NOT NULL UNIQUE | MD5 去重，防重复上传 |
| `width` | INT | - | 图片宽度 px |
| `height` | INT | - | 图片高度 px |
| `format` | VARCHAR(8) | - | jpg / png / gif / webp |
| `file_size` | INT | - | 文件大小 Bytes |
| `uploader_id` | BIGINT | NOT NULL FK→users | 上传者 |
| `description` | VARCHAR(200) | - | 文字描述 → `MemeItem.title`，同时用于 CLIP 文本编码 |
| `source_type` | TINYINT | DEFAULT 0 | 0=用户上传, 1=种子数据, 2=社区创作 → `MemeItem.source` |
| `status` | TINYINT | DEFAULT 1 | 0=待审核, 1=正常, 2=屏蔽 |
| `like_count` | INT | DEFAULT 0 | 点赞数冗余 → `MemeItem.likeCount` |
| `collect_count` | INT | DEFAULT 0 | 收藏数冗余 |
| `comment_count` | INT | DEFAULT 0 | ⚠️ 评论数冗余（建议新增 → `MemeItem.commentCount`） |
| `created_at` | DATETIME | DEFAULT NOW() | 上传时间 → `MemeItem.createdAt` |

**涉及页面：** HomeScreen, CommunityScreen, RankingScreen, ProfileScreen

### 3.2 检索说明

> AI 多模态检索（拍照/文字/以图搜图）由 **AI 组** 独立负责，包括特征提取、向量存储和相似度匹配。
> Android 端通过 `MemeApi.searchMemes()` 调用 AI 组接口，传入 query + mode，直接获取 Top-K 的 `emoji_id` 列表。
> 因此本库 **不建** 特征向量表，与 AI 组的边界通过 API 解耦。

## 七、实时互动

### 7.1 danmaku_rooms（斗图房间表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PK AUTO_INCREMENT | - |
| `name` | VARCHAR(50) | NOT NULL | 房间名称 → `BattleRoom.name` |
| `creator_id` | BIGINT | NOT NULL FK→users | 创建者 |

**消息策略：** 弹幕消息不持久化到 MySQL。进入房间时从 Redis 取最近 20 条；WebSocket 实时推送。历史消息不保留（选题报告明确）。

**涉及页面：** BattleScreen（8 个主题房间列表 + 创建 FAB）

### 7.2 game_matches（模仿大赛对局表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PK AUTO_INCREMENT | - |
| `room_id` | BIGINT | FK→danmaku_rooms | 可以为 NULL（独立匹配） |
| `round_num` | INT | NOT NULL | 第几轮 |

**涉及页面：** ImitationContestScreen（4 阶段: IDLE→MATCHING→PLAYING→JUDGING→RESULT）

### 7.3 game_participants（对局参与者表）🆕

> 替代原 `participants_json` + `scores_json`，结构化存储方便查历史战绩。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PK AUTO_INCREMENT | - |
| `match_id` | BIGINT | NOT NULL FK→game_matches CASCADE | 所属对局 |
| `user_id` | BIGINT | NOT NULL FK→users | 参与者 |
| `score` | INT | DEFAULT 0 | AI 评分 0-100 |
| `photo_url` | VARCHAR(512) | - | 用户模仿自拍的图片路径 |
| `created_at` | DATETIME | DEFAULT NOW() | - |

**唯一约束：** UNIQUE(match_id, user_id)
**查询示例：**
```sql
-- 用户历史最高分
SELECT MAX(score) FROM game_participants WHERE user_id = ?;
-- 本周模仿王（排行榜）
SELECT user_id, COUNT(*) AS wins FROM game_participants
WHERE score = (SELECT MAX(score) FROM game_participants p2 WHERE p2.match_id = game_participants.match_id)
GROUP BY user_id ORDER BY wins DESC LIMIT 10;
```

**涉及页面：** ImitationContestScreen 结果排名列表

### 10.2 对比原方案新增/建议修改的字段

| 表 | 变更 | 原因 |
|----|------|------|
| `emojis` | + `thumbnail_url` VARCHAR(512) | 瀑布流需要缩略图，否则原图加载太慢 |
| `emojis` | + `comment_count` INT DEFAULT 0 | 与 `like_count` 一致，减少 JOIN |
| `bounties` | + `accepted_emoji_id` BIGINT FK | 只记录 accepted_user_id 不够，需要知道采纳了哪个表情包 |
| `game_matches` | - `participants_json` | 拆为 `game_participants` 表 |
| `game_matches` | - `scores_json` | 同上 |

### 10.3 🆕 补充的三张表

| 表名 | 必须/建议 | 对应页面 |
