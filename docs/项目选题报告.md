## 一、项目背景与选题依据

### 1.1 现实需求分析

在当今移动社交场景中，表情包已成为用户表达情绪、调节聊天气氛和传递态度的重要媒介。以微信聊天为例，用户在对话中经常遇到一种高频但难以解决的需求：**此刻想发一个表达特定情绪的表情包，脑海中已经浮现出画面感，但在收藏夹、相册或聊天记录中却很难快速找到。**

具体而言，这种需求体现在以下三个维度：

1. **情绪驱动的检索需求：** 用户通常以「我现在想表达什么」为出发点——比如想发一个「无语」「破防」「憋笑」的表情包。这是一种语义层面的检索需求，而非关键词匹配能解决。
2. **图像化记忆的匹配需求：** 用户对表情包的记忆往往是画面化的——记得某个表情里有「皱眉的人」「夸张的猫脸」「崩溃的姿势」——但说不出精确的标签或文件名。用户需要一种「以图搜图」或「以描述搜图」的能力。
3. **实时表情映射需求：** 用户在聊天时会产生自发的情绪反应，如果能通过摄像头捕捉当前表情，自动匹配相似的表情包，将是极为自然的交互方式。

据观察，单个活跃微信用户的表情包收藏量通常在200-2000张之间，但日常真正能被快速找到并使用的不足10%。这说明**表情包的管理与检索存在显著的用户痛点。**

### 1.2 现有方案的不足

当前主流的表情包解决方案存在以下局限：

| 方案 | 核心问题 |
|------|---------|
| **微信收藏表情** | 上限999个；仅支持按添加时间排序，无搜索能力；是「私人工具箱」而非「开放素材库」 |
| **输入法表情搜索** | 依赖关键词匹配，无法理解语义和图像特征；表情库质量参差不齐、版权不明 |
| **相册手动翻找** | 效率极低；表情包与生活照片混杂，无分类体系 |
| **搜索引擎图片搜索** | 非表情包专用，结果多为普通图片；无法与聊天场景衔接 |
| **专门表情包App** | 多为浏览下载工具，缺少移动端智能检索能力；无社交和创作生态 |

**关键洞察：** 微信提供了最便捷的表情包使用入口，但它本质上是一个「私人保存箱」——用户只能靠自己积累，无法利用他人的表情包资产，也无法参与表情包的创作和社区传播。市场上缺少一个**以AI检索为核心能力、以用户众包为内容来源、以轻社交为传播渠道**的表情包平台。

### 1.3 选题意义与价值

本项目「表情云库」的选题具有以下意义：

1. **解决真实痛点：** 直接回应「想发表情包但找不到」的高频用户需求，有明确的实用价值。
2. **技术融合创新：** 将多模态AI（计算机视觉 + 自然语言处理）应用于表情包检索场景，体现了前沿技术在日常场景中的落地可能。
3. **差异化定位明确：** 与微信形成互补而非竞争关系——微信是「私人工具箱」，我们是「开放众包表情库 + 轻创作社区」。用户在我们平台找到表情包后，一键保存到微信使用，形成互补生态。

## 二、项目目标

本项目旨在构建一个集「表情包智能检索」与「表情包社交分享」于一体的移动端应用——「表情云库」。具体目标如下：

1. **实现多模态表情包检索：** 支持用户通过拍照识别面部表情/身体动作、输入文字描述、上传图片三种方式，从表情库中快速检索匹配的表情包，返回Top-K结果。
2. **实现表情包众包管理：** 用户可上传个人收藏的表情包并添加标签，系统表情库随用户贡献持续增长，形成「人人贡献、人人受益」的数据飞轮。
3. **实现表情包轻创作功能：** 用户可使用自己的照片配合模板和配文，创作新的表情包并发布到社区广场。
4. **实现轻量社交功能：** 包括社区广场（表情包浏览与互动）、排行榜（热梗排名）、弹幕斗图室（实时表情包交流）、话题挑战、好友关注和表情包悬赏。

## 三、功能说明

### 3.1 功能总览

「表情云库」围绕三条核心业务线构建功能体系：

```
表情云库 = 检索（消费） + 创作（生产） + 社交（传播）

┌──────────────────────────────────────────────────────────────┐
│  检索线（消费侧）       创作线（生产侧）      社交线（传播侧）│
│  ──────────────        ──────────────      ──────────────   │
│  拍照→AI映射→匹配      用户上传表情包       排行榜            │
│  文字描述→语义搜索     拍照创作新表情       弹幕斗图室        │
│  图片→以图搜图         +模板配文发布        话题挑战          │
│  标签分类浏览          优质内容入库         好友关注          │
│                                             表情包悬赏        │
│                                             表情包模仿大赛    │
└──────────────────────────────────────────────────────────────┘
```

**核心闭环：** 用户通过AI检索引擎消费表情包 → 用户创作上传新表情包 → 优质社区内容被收录入库 → 检索库更丰富 → 吸引更多用户 → 更多创作上传。形成**「消费 → 生产 → 增长 → 更好消费」的良性数据飞轮。**

### 3.2 模块一：AI智能检索（核心——消费侧）

**做什么：** 提供三种检索入口，帮助用户从表情库中快速找到想要的表情包。这是产品最核心的使用场景。

#### 3.2.1 拍照映射检索

用户通过摄像头拍摄自己的面部表情或身体动作，系统通过队友开发的AI表情/动作分类模型（基于MobileNetV3）识别用户的情绪和动作类别，然后在表情库中检索最匹配的表情包。

**典型场景：**
- 用户觉得自己此刻的表情就是「无语」，打开相机拍一张
- 系统识别出「翻白眼 + 嘴角下拉」的微表情
- 返回「熊猫人无语」「猫猫叹气」等N个匹配表情包
- 用户一键保存到手机，在微信聊天中使用

**关键交互：**
- 拍照前显示3-2-1倒计时动画
- 拍照后显示进度条，标注「识别中…」
- 识别失败时引导用户调整光线或姿势重试
- 结果按相似度降序排列，支持滑动浏览和点击查看详情

#### 3.2.2 文字语义检索

用户输入自然语言描述（如「一只崩溃的猫」「笑着笑着就哭了」），系统通过Chinese-CLIP模型将文字编码为语义向量，与表情库中的图片特征进行跨模态相似度匹配。

**典型场景：**
- 用户在聊天中想回一个表达「表面冷静内心崩溃」的表情
- 在搜索框输入「强颜欢笑」
- 系统返回语义相关的表情包（不需要精确标签匹配）

**关键交互：**
- 搜索框常驻首页顶部，支持实时搜索建议
- 空状态引导：展示热门搜索词供用户快速选择
- 支持按热度/相关度排序

#### 3.2.3 以图搜图

用户上传已有图片（如从聊天记录中保存的小图、截图等），系统通过CLIP图像编码器提取视觉特征，在表情库中进行相似度检索。

**典型场景：**
- 用户有一个模糊的小图表情包，想要高清版本或同类表情
- 上传后系统返回视觉上最相似的N个结果

#### 3.2.4 标签分类浏览

按预设标签（#搞笑 #猫 #打工人 #熊猫人 #震惊 #无语 #破防 等）进行瀑布流浏览，适合用户无明确目标时的探索性浏览。

### 3.3 模块二：表情包众包管理（核心——生产侧）

**做什么：** 提供表情包的上传、管理、收藏功能，让用户不仅是消费者，也是内容贡献者。这是产品内容持续增长的基础。

#### 3.3.1 表情包上传

用户将自己收藏的表情包上传到平台，填写标签和描述。上传后系统自动进行特征提取并建立索引，使该表情包可被检索。

**关键设计：**
- 支持JPG/PNG/GIF/WEBP格式，单文件≤10MB
- 上传后5秒内完成特征提取并加入检索索引
- 自动压缩大图以优化存储和传输

#### 3.3.2 个人表情库

查看和管理自己上传及收藏的所有表情包，支持分类查看和删除。

#### 3.3.3 收藏与历史记录

- 收藏：一键收藏检索结果或社区中看到的表情包
- 历史记录：查看最近30天的检索和浏览记录，支持一键复用历史搜索

---

### 3.4 模块三：社区广场（核心——内容消费）

**做什么：** 展示用户原创/新创作的表情包（**不含**检索库已有内容，避免重复），以双列瀑布流形式呈现。用户可以浏览、点赞、评论，这是「创作线」的核心承载页面，也是构建社区氛围的基础。

**为什么社区广场只展示用户原创内容？**
- 检索库是「工具资产」——用户上传的现成表情包合集，供所有人检索消费
- 社区广场是「创作展示」——用户用自己的照片、创意制作的新表情包，有更强的社交属性和互动价值
- 两者定位不同，混在一起会稀释社区的原创氛围

**关键交互：**
- 双列瀑布流（Masonry/Staggered Layout），图片优先，信息轻量
- 支持「推荐/最新/关注」三种内容筛选
- 下拉刷新 + 上滑加载更多
- 点赞使用乐观更新（先更新UI，后同步服务端），心形动画+数值+1
- 删除确认弹窗：「确定删除这个表情包吗？删除后无法恢复」
- 图片加载失败时显示灰色占位图

**表情包创作发布流程：**
1. 用户点击底部「+」发布按钮进入创作页
2. 拍照或从相册选择照片
3. 添加配文（可选）
4. 选择风格模板（可选）
5. 添加标签（推荐至少1个）
6. 预览 → 确认发布
7. 发布成功后自动跳转到社区广场，新帖子即时可见

### 3.5 模块四：社交互动（重要——增强用户粘性）

**做什么：** 在核心检索和管理功能之上，提供轻量级社交功能，增强用户参与感和平台粘性，构建差异化竞争力。

#### 3.5.1 排行榜

按点赞数和使用量排名表情包的榜单系统，包含三个维度：
- **今日最火：** 24小时内热度排名
- **本周最热：** 7天内综合热度排名
- **总榜：** 历史累计排名

排行榜从社区广场入口进入，激发用户的创作竞争意识。

#### 3.5.2 弹幕斗图室

实时房间制的表情包互动空间。用户进入房间后只能发表情包（不能发文字），表情包以弹幕形式从右到左滚动展示。这是产品社交差异化的重要功能——与普通聊天室不同，这里**纯表情包交流**，为用户提供一种全新的娱乐体验。

**关键特性：**
- 基于WebSocket实时通信，消息延迟<500ms
- 支持从个人表情库、检索结果、即时拍照三种方式选择表情包发送
- 表情包弹幕从右到左滚动，类似视频弹幕但内容为表情包
- 单房间人数上限50人，超出后新用户可旁观但不可发送
- 单用户每秒最多发送2条，防止刷屏
- 创建后2小时无活动自动关闭
- 用户离开后不保留历史消息，进入时仅加载最近20条

**典型场景：**
- 用户无聊时进入斗图室，看到满屏表情包弹幕飞过，被逗笑
- 选择自己的表情包加入「斗图」，比拼谁的图更有梗
- 在欢声笑语中度过碎片时间

#### 3.5.3 话题挑战

每日发布一个创作主题（如「#用表情包表达周一的心情#」），用户围绕主题创作并投稿，其他用户投票。每天评选当日最佳。

**关键流程：** 系统发布每日话题 → 用户创作投稿 → 社区投票 → 揭晓当日最佳 → 获奖者获得积分/徽章

#### 3.5.4 好友关注体系

- 关注/取关其他用户
- 查看关注者的最新发布内容（在社区广场中筛选「关注」Tab）
- 关注动态通知

#### 3.5.5 表情包悬赏

用户发布悬赏需求（如「求一张表达甲方改需求时内心崩溃的表情包」），其他用户可以帮找或帮忙创作，采纳者可获得积分奖励。这创造了一种**需求驱动的表情包创作场景**，丰富了平台的互动方式。

#### 3.5.6 表情包模仿大赛

实时多人竞技的游戏化功能。系统随机展示一张表情包作为「模仿目标」，参赛用户在限定时间内（如15秒）用摄像头拍摄自己模仿该表情包的动作和神态，AI模型对每位用户的模仿进行相似度打分，得分最高者获胜。

**关键特性：**
- 基于WebSocket实时通信，所有参赛者同步进入比赛轮次
- 每轮比赛3-5人匹配，系统随机分配对手
- 系统展示目标表情包+15秒倒计时，倒计时结束自动拍照
- AI模型对比用户自拍与目标表情包的面部表情/身体动作相似度，给出0-100评分
- 比赛结束后展示本轮排名和各人得分，胜者获得积分
- 支持连续匹配和多轮比赛，积分累加计入排行榜

**典型场景：**
- 用户进入模仿大赛，点击「开始匹配」
- 系统匹配到3名对手，展示一张「熊猫人震惊」表情包
- 15秒倒计时，所有用户对着摄像头模仿「震惊」表情
- 倒计时结束，AI自动打分并公布排名
- 用户看到自己和对手的得分对比，欢笑中进入下一轮

### 3.6 功能优先级划分

考虑到4人团队和5天开发周期，所有功能均在短期内交付，按以下优先级推进：

| 优先级 | 模块 | 包含功能 | 计划时间 |
|--------|------|---------|---------|
| 🔴 **最高优先** | AI智能检索 | 拍照映射、文字语义搜索、以图搜图、标签浏览 | Day 1-2 |
| 🔴 **最高优先** | 表情包管理 | 上传、个人库、收藏、历史记录 | Day 1-2 |
| 🔴 **最高优先** | 用户系统 | 注册登录、个人中心 | Day 1-2 |
| 🔴 **最高优先** | 社区广场 | 瀑布流、表情包详情、点赞评论、创作发布 | Day 2-3 |
| 🟡 **高优先** | 弹幕斗图室 | WebSocket实时通信、房间管理、弹幕展示 | Day 3-4 |
| 🟡 **高优先** | 表情包模仿大赛 | 实时匹配、限时模仿、AI打分、排名展示 | Day 3-4 |

## 四、技术路线概述

本项目采用 **Android原生客户端 + FastAPI后端 + AI推理服务** 的三层架构：

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端** | Kotlin + Jetpack Compose | Android原生开发，CameraX相机集成，Coil图片加载，OkHttp网络请求+WebSocket |
| **后端** | Python FastAPI | 异步高性能框架，原生WebSocket支持，SQLAlchemy ORM，JWT认证 |
| **AI推理** | Chinese-CLIP + MobileNetV3 + FAISS | CLIP负责多模态特征提取和跨模态匹配；MobileNetV3（队友开发）负责表情/动作分类映射；FAISS负责向量相似度检索 |
| **数据存储** | MySQL/PostgreSQL + MinIO | 关系数据库存元数据和用户数据，MinIO对象存储存图片文件 |
| **实时通信** | WebSocket | 弹幕斗图室和表情包模仿大赛的实时通信，前端OkHttp WebSocket + 后端FastAPI WebSocket，支持房间匹配和实时广播 |

**架构分层：**

```
Android客户端
    ↓ HTTP/WebSocket
FastAPI后端（API层 → 业务逻辑层 → AI推理层 → 数据层）
    ↓
MySQL + MinIO + FAISS索引
```

**关键技术说明：**

1. **AI定位修正：** 本项目不使用生成式AI（扩散模型/GAN等），以免引入不可控的生成质量问题。AI模型专注于**映射检索**——将用户的输入（照片/文字/图片）映射到已有表情库中的匹配项，保证输出质量可控、可预期。
2. **Chinese-CLIP使用预训练模型：** 无需从头训练，直接用于图文跨模态特征提取和匹配。
3. **队友的MobileNetV3表情映射模型：** 轻量级分类网络，可部署于服务端，完成从用户自拍到表情类别的映射。

## 五、项目特色与创新点

1. **多模态融合检索：** 不是单一的文字搜索或标签筛选，而是将「拍照+文字+图片」三种输入模式统一到同一检索框架下，覆盖用户在不同场景下的检索需求。

2. **AI映射而非AI生成：** 不做不可控的AI表情包生成，而是聚焦于可落地的表情/动作→现有表情包的智能映射。这保证了输出结果的可用性，也降低了技术风险和开发难度。

3. **「消费—生产—传播」三位一体闭环：** 不是单向的检索工具，而是构建了完整的表情包生态——检索满足消费需求，创作满足生产需求，社区满足传播需求，三者相互促进。

4. **弹幕斗图室——纯表情包社交空间：** 区别于传统文字聊天室，这是一个只能用表情包「说话」的互动空间，将表情包的娱乐属性发挥到极致。

5. **表情包模仿大赛——AI驱动的实时竞技：** 将AI表情识别能力转化为游戏化竞技体验。用户限时模仿目标表情包，AI实时打分排名，将表情包的娱乐性从「被动浏览」升级为「主动参与」，增强了产品的互动深度和用户粘性。

6. **与微信互补而非竞争：** 产品定位为微信的「上游内容供给方」——用户在我们的平台发现和创作表情包，然后保存到微信使用。微信的表情包功能越强大，用户对优质表情包的需求越大，我们的价值越凸显。

7. **众包驱动的数据飞轮：** 用户越多→上传越多→表情库越丰富→检索效果越好→吸引更多用户，形成自我强化的增长逻辑。
