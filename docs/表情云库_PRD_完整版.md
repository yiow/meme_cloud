## 1. 产品概述

### 一句话定位

> 这是一个给**年轻表情包用户**用的 **Android 应用**，帮他们**快速检索找到合适的表情包，同时支持用户创作上传新表情包，形成一个众包增长的表情包管理与分享平台**。
>
> 与微信表情包相比，核心差异是：**微信是私人工具箱，我们是开放的众包表情库 + 轻创作社区。**

### 产品本质

```
产品 = 表情包检索工具 + 众包表情库 + 轻创作社区

      检索（消费）          创作（生产）           社交（传播）
      ──────────          ──────────           ──────────
      自拍/文字/图片       用户用自己照片          排行榜
      → AI映射匹配         +模板/配文创作        斗图室
      → 从库里找到         → 发布到广场          话题挑战
        最像的表情包        → 优质内容入库        关注体系
                              ↓                 悬赏求图
                          表情库持续增长
```

---

### 1.1 项目背景

在移动社交场景中，表情包已经成为用户表达情绪、调节聊天气氛和传递态度的重要媒介。以微信聊天为例，用户在对话中经常会出现一种具体但难以表达的需求：此刻想发一个「无语」「尴尬」「破防」「憋笑」或者「震惊」的表情包，脑海中也许已经浮现出某种画面，但在收藏夹、相册或聊天记录中却很难快速找到。

传统表情包管理方式主要依赖关键词命名、人工分类、最近使用记录或相册查找。这种方式与人的记忆方式并不完全一致。用户对表情包的记忆往往是图像化和场景化的：可能记得画面里有一个皱眉的人、一个夸张的猫脸、一个桌面上的崩溃姿势，或者记得当前摄像头拍到的场景与某类表情包很像，却不一定记得准确标签。由此，本项目提出「基于移动端的多模态表情包智能检索与推荐系统」，尝试把文字描述、上传图片和实时摄像头内容都作为检索入口。

本系统面向课程实践场景，目标不是构建商业级推荐平台，而是完成一个可运行、可演示、文档完整的软件工程项目。系统将通过 Android 原生应用提供移动端交互，通过 FastAPI 后端完成图片接收、文本接收、特征提取、相似度计算和 Top-K 推荐结果返回，使用户能够更自然地从表情包库中找到符合当前聊天语境的表情包。

> **【本次更新】** 在原有检索功能基础上，项目进行了重大方向升级——从「表情包检索工具」扩展为「表情包众包管理与社交分享平台」。新增社交功能包括社区广场、排行榜、弹幕斗图室、话题挑战、好友关注体系和表情包悬赏，构建「AI映射检索（消费）+ 用户创作上传（生产）+ 社区互动（传播）」三位一体的产品闭环。

---

### 1.2 项目目标

> **【本次更新】** 本项目旨在构建一个集「表情包智能检索」与「表情包社交分享」于一体的移动端应用——「表情云库」。具体目标如下：

1. **实现多模态表情包检索功能**：支持用户通过拍照识别面部表情/身体动作、输入文字描述、上传图片三种方式，从表情库中快速检索匹配的表情包。
2. **实现表情包众包管理**：用户可上传个人收藏的表情包并添加标签，系统表情库随用户贡献持续增长，形成「人人贡献、人人受益」的数据飞轮。
3. **实现表情包轻创作功能**：用户可使用自己的照片配合模板和配文，创作新的表情包并发布到社区广场。
4. **实现轻量社交功能**：包括社区广场（表情包发布与浏览）、排行榜（热梗排名）、弹幕斗图室（实时表情包交流）、话题挑战（每日主题创作）、好友关注体系和表情包悬赏。
5. **完成课程实践要求**：交付可运行、可演示的 Android 应用，以及完整的软件工程文档（需求、设计、测试、答辩材料）。

---

### 1.3 项目范围

本项目主要完成用户端、后端服务和数据管理三类功能。用户端负责首页展示、图片上传检索、拍照检索、文字描述检索、推荐结果展示、表情包详情查看、收藏、历史记录和分类浏览。后端负责接收图片与文字请求、完成图片预处理、提取图片或文本特征、计算相似度、返回 Top-K 推荐结果，并管理表情包元数据、收藏记录和搜索历史。数据管理部分负责表情包图片存储、标签与分类维护、特征向量缓存以及用户行为记录存储。

> **【本次更新】** 项目范围从原有的「检索工具」扩展为「表情包管理+社交平台」，新增以下范围：
>
> 1. **社交功能模块**：社区广场（内容瀑布流）、排行榜系统、弹幕斗图室（WebSocket实时通信）、话题挑战、好友关注体系、表情包悬赏。
> 2. **创作功能模块**：用户可使用自己的照片配合模板/配文创作新表情包，发布到社区广场。
> 3. **AI映射模块**：利用队友开发的表情-动作到表情包的映射模型，实现拍照后智能匹配。

**项目不做什么（边界）：**

- ❌ 不开发大型社交聊天平台
- ❌ 不进行复杂用户关系管理
- ❌ 不实现真实商业级个性化推荐系统
- ❌ 不训练大型生成式AI模型（扩散模型/GAN等）
- ❌ 不涉及敏感人脸身份识别或真实身份认证
- ❌ 不做 iOS 版本——聚焦 Android
- ❌ 不做即时通讯（IM）
- ❌ 不做表情商店/支付系统
- ❌ 社区广场不重复展示检索库里已有的表情包——只展示用户新创作的内容

## 2. 可行性分析

> **【本次更新】** 以下从技术、团队、市场三个维度进行可行性分析。

### 2.1 技术可行性

| 技术项 | 方案 | 可行性说明 |
|--------|------|-----------|
| 多模态检索 | Chinese-CLIP 预训练模型 | 无需从头训练，直接用于图文跨模态检索 |
| AI映射模块 | MobileNetV3 | 轻量级分类网络，可部署于移动端或服务端 |
| 后端服务 | FastAPI | 异步高性能，原生支持 WebSocket |
| Android前端 | Kotlin + Jetpack Compose | 现代 UI 框架，CameraX 支持相机调用 |
| 数据库 | MySQL/PostgreSQL | 成熟稳定，满足元数据存储需求 |
| 图片存储 | MinIO / 本地文件系统 | 对象存储方案，易于扩展 |
| 向量检索 | FAISS | Facebook 开源，高效相似度搜索 |

### 2.2 团队可行性

- 团队共 **3 名开发人员**，分别负责 Android 前端、后端+AI集成、AI模型开发
- 队友已在开发表情/动作映射模型，可直接集成到系统中
- 短学期周期，功能范围按优先级分层可控
- MVP 可在短期内完成核心检索 + 社区广场

### 2.3 市场可行性

- 表情包是年轻用户日常社交的高频刚需，微信表情包用户基数大但功能偏向工具化
- 本产品差异化明确：「开放的众包表情库+社区」vs 微信的「私人工具箱」，不正面竞争
- 以答辩演示和课程实践为主要目标，验证产品概念即可，不追求商业化上线

## 3. 系统建设内容

### 3.1 功能模块

> **【本次更新】** 系统共包含六大功能模块，按优先级分为核心模块（🔴）、重要模块（🟡）和未来规划（⚪）。

```
表情云库
│
├── 🔴 模块一：AI智能检索模块（核心，MVP 必须有）
│   ├── 拍照检索：调用摄像头捕捉用户面部表情/身体动作，
│   │             通过AI映射模型匹配表情库中最相似的表情包
│   ├── 文字检索：输入自然语言描述（如「一只崩溃的猫」），
│   │             通过CLIP文本编码匹配图像特征
│   ├── 以图搜图：上传已有图片，提取图像特征后在表情库中进行相似度检索
│   └── 标签分类浏览：按预设标签（#搞笑 #猫 #打工人 #熊猫人 等）进行瀑布流浏览
│
├── 🔴 模块二：表情包管理模块（核心，MVP 必须有）
│   ├── 表情包上传：用户上传个人收藏的表情包，填写标签、描述
│   ├── 个人表情库：查看、管理自己上传和收藏的表情包
│   ├── 收藏功能：收藏喜欢的表情包到个人库
│   └── 历史记录：查看最近的检索和浏览记录
│
├── 🔴 模块三：社区广场模块（核心，MVP 必须有）
│   ├── 内容瀑布流：展示用户原创/新创作的表情包
│   │               （非检索库已有内容，避免重复）
│   ├── 表情包详情：查看表情包大图、作者信息、点赞评论数
│   ├── 点赞/评论：对社区中的表情包进行互动
│   └── 发布创作：用户用自己照片+模板/配文创作新表情包发布到广场
│
├── 🟡 模块四：社交互动模块（重要，第二阶段实现）
│   ├── 排行榜：今日最火/本周最热/总榜，按点赞数和使用量排名
│   ├── 弹幕斗图室：实时房间制，仅支持发表情包，弹幕式滚动展示
│   ├── 话题挑战：每日主题创作挑战（如#用表情包表达周一的心情#），投稿+投票
│   ├── 好友关注：关注/取关用户，查看关注者的最新发布
│   └── 表情包悬赏：发布悬赏需求，其他用户帮找或创作，采纳者可获积分
│
├── ⚪ 模块五：用户系统（未来规划）
│   ├── 成就系统：发布量/获赞量/连续打卡等徽章和等级
│   ├── 情绪日历：基于每日打卡生成个人情绪时间线
│   └── 表情包合辑：创建主题合辑（如「打工人专用」「猫猫合集」）
│
└── ⚪ 模块六：AI增强模块（未来规划）
    ├── 智能配文：上传图片自动生成多条梗图文案供选择
    ├── 表情包质量评分：基于社区反馈自动评估内容质量
    └── 个性化推荐：基于用户浏览/点赞历史的轻量推荐
```

### 3.2 功能优先级与迭代计划

> **【本次更新】** 考虑短学期时间约束（约3-4周）和3人开发团队，按以下优先级分批交付：

| 阶段 | 时间 | 内容 |
|------|------|------|

## 4. 技术路线与总体架构

### 4.1 技术路线

> **【本次更新】** 以下是完整技术选型：

**前端：Android 原生应用**
- 开发语言：Kotlin（推荐）或 Java
- UI框架：Jetpack Compose（推荐）或 XML + Material Design
- 网络请求：Retrofit + OkHttp
- 图片加载：Glide / Coil
- 实时通信：OkHttp WebSocket
- 相机：CameraX

**后端：Python FastAPI**
- 框架：FastAPI（异步高性能，适合AI推理接口）
- 实时通信：FastAPI WebSocket
- ORM：SQLAlchemy
- 认证：JWT Token

**AI推理服务**
- 特征提取：Chinese-CLIP（OpenCLIP / HuggingFace Transformers）
- 表情/动作识别：队友开发的轻量分类模型（MobileNetV3）
- 向量检索：FAISS（Facebook AI Similarity Search）
- 推理框架：ONNX Runtime 或 PyTorch

**数据库与存储**
- 关系数据库：MySQL 8.0 / PostgreSQL
- 图片存储：MinIO（对象存储）或本地文件系统
- 向量索引：FAISS 内存索引（支持持久化）

**部署方案（答辩用）**
- 后端+AI服务部署于单台服务器或本地笔记本
- Android APK 直接安装演示
- 可选：使用 Ngrok 实现内网穿透供外网访问

## 13. 核心功能详细描述

> **【本次更新】** 以下对每个🔴核心功能进行详细描述，包含交互细节、状态清单、边界条件和数据规范。

### 功能A：AI表情-动作映射检索

**功能描述：** 用户通过摄像头拍摄自己的面部表情或身体动作，系统通过AI模型识别表情/动作类别，在表情库中检索最匹配的表情包，返回Top-K结果。

**核心逻辑：** 拍照 → 人脸/动作检测 → 轻量分类模型推理 → 特征向量匹配 → FAISS检索 → Top-K返回。

**触发条件：** 用户在首页点击「拍照搜图」按钮或在检索Tab中选择「拍照」入口。

#### 交互细节

| 场景 | 交互处理方式 |
|------|------------|
| **操作反馈** | 点击拍照后显示3-2-1倒计时动画 → 拍照完成显示缩略图+进度条 → 检索完成展示结果网格 |
| **空状态引导** | 首次使用时展示引导浮层：「对着摄像头做一个表情，帮你找到最像的表情包！」 |
| **操作失败引导** | 识别失败：「没看清你的表情呢~ 请对准脸部，光线亮一点试试」；无匹配结果：「表情库中还没找到相似的，试试用文字描述搜索吧」 |
| **危险操作确认** | 无（纯查询操作，不涉及删除/修改） |

#### 状态清单

| 状态 | 触发条件 | UI表现 | 用户可执行操作 |
|------|---------|--------|-------------|
| **默认** | 页面加载完成 | 相机预览画面 + 拍照按钮 + 检索方式切换 | 点击拍照/切换镜头；选择其他检索方式 |
| **加载中** | 拍照后触发 | 缩略图 + 加载进度条 +「识别中…」文案 | 不可重复触发；可取消（超时后） |
| **成功** | 检索返回结果 | 结果网格/列表 + 相似度百分比 +「找到N个匹配」 | 点击查看详情；滑动查看更多；保存/收藏/分享 |
| **失败** | 识别失败或网络错误 | 错误提示 + 重新拍照按钮 + 备选检索方式 | 重新拍照；切换到文字检索 |
| **空结果** | 无匹配表情包 | 空状态插画 + 引导文案 + 文字搜索入口 | 尝试其他检索方式；上传新表情包 |

#### 边界条件

- **无摄像头权限时：** 弹出权限申请弹窗，说明需要相机的理由，提供「去设置」按钮
- **拍照质量过低时：** 提示「画面太暗/模糊，请调整光线或稳定手机」
- **网络超时（>10秒）：** 自动取消请求，提示「网络不太稳定，请重试」+ 重试按钮
- **多人脸检测到时：** 取最大的人脸进行分析，小字提示「已识别画面中最大的人脸」
- **无人脸检测到时：** 提示「未检测到人脸，试试上传图片搜索或文字搜索」
- **图片过大时：** 自动压缩至 1024x1024 以内再上传

#### 数据规范

| 字段名 | 数据类型 | 长度/大小限制 | 是否必填 | 默认值 | 格式要求 | 校验规则 |
|--------|---------|------------|--------|------|--------|--------|
| 图片文件 | File | ≤10MB | 是 | 无 | JPG/PNG/GIF/WEBP | 文件类型+大小校验 |
| 检索方式 | String | - | 是 | camera | camera/text/image | 枚举值 |
| 返回数量 | Int | 5-20 | 否 | 10 | 正整数 | 范围校验 |
| 置信度阈值 | Float | 0-1 | - | 0.5 | 小数点2位 | 范围校验 |

### 功能B：社区广场（内容浏览与互动）

**功能描述：** 社区广场展示用户原创/新创作的表情包（非检索库已有内容，避免重复），以瀑布流形式呈现。用户可浏览、点赞、评论，并点击进入详情页。这是「创作线」的核心承载页面。

**触发条件：** 用户点击底部Tab「社区」进入。

#### 交互细节

| 场景 | 交互处理方式 |
|------|------------|
| **操作反馈** | 下拉刷新：顶部加载动画；上滑加载更多：底部加载指示器；点赞：心形动画 + 数值+1（乐观更新）；发布成功：toast「发布成功」+ 自动回顶部刷新 |
| **危险操作确认** | 删除自己的帖子：底部弹窗「确定删除这个表情包吗？删除后无法恢复」[取消] [确认删除]（红色） |
| **空状态引导** | 无内容时显示空状态插画 +「还没有人分享表情包~ 来做第一个贡献者吧！」[去创作] 按钮 |
| **操作失败引导** | 加载失败：提示+重试按钮；发布失败：toast具体原因+保留草稿 |

#### 边界条件

- **内容为空时：** 展示空状态引导，推荐去「话题挑战」参与创作
- **网络异常时：** 显示离线提示+重试按钮，已加载内容保持可见
- **图片加载失败时：** 显示灰色占位图+裂图图标
- **评论字数上限：** 200字，超出时输入框变红+计数提示（如「185/200」）
- **并发点赞：** 使用乐观更新+服务端去重，避免重复计数
- **帖子去重：** 同一用户30秒内不能发布相同图片（MD5校验）

### 功能C：弹幕斗图室

**功能描述：** 用户进入斗图房间后，只能发表情包进行实时互动。表情包以弹幕形式从右到左滚动展示。支持从个人表情库、检索结果或即时拍照映射三种方式选择表情包发送。这是产品社交差异化的重要功能。

**触发条件：** 用户点击底部Tab「斗图」进入房间大厅，选择或创建房间。

#### 交互细节

| 场景 | 交互处理方式 |
|------|------------|
| **进入房间** | Toast「进入了 XXX 房间」；弹幕区显示最近20条消息；在线人数实时更新 |
| **发送表情包** | 底部弹出表情包选择器（半屏）；选中后立即发送，弹幕区出现；自己的表情包带边框高亮标记 |
| **危险操作** | 退出房间：无确认（低风险操作）；举报表情包：长按→「举报」→确认弹窗 |
| **空状态引导** | 房间无人时：「这个房间还没人说话，发个表情包暖暖场吧！」 |
| **连接断开** | 弹幕区顶部红色提示条「连接已断开，正在重连…」；重连成功后绿色提示「已重连」 |

#### 边界条件

- **单房间人数上限：** 50人，超出后新用户只能旁观（不能发送）
- **消息频率限制：** 单用户每秒最多发送2条，超出时提示「发太快了，歇一歇~」
- **WebSocket断连：** 自动重试3次，每次间隔2秒；3次失败后提示手动重连
- **房间生命周期：** 创建后2小时无活动自动关闭
- **表情包文件：** 仅支持JPG/PNG/GIF（斗图室不支持视频），GIF自动播放
- **离线消息：** 用户离开后不保留历史消息，进入时仅加载最近20条

## 16. 非功能性需求

> **【本次更新】**

### 性能要求

| 指标 | 目标值 |
|------|--------|
| 首页启动时间 | < 2秒 |
| 拍照检索接口响应 | < 3秒（含AI推理） |
| 文字检索接口响应 | < 2秒 |
| 瀑布流图片加载 | < 1秒/张 |
| WebSocket消息延迟 | < 500ms |
| 表情包上传 | < 5秒（含特征提取） |

### 权限控制

- 浏览社区广场无需登录
- 发布内容、点赞评论需要登录
- 弹幕斗图室发言需要登录（旁观无需登录）
- 无角色权限区分（MVP阶段所有登录用户权限相同）

### 兼容性

- 支持 Android 8.0（API 26）及以上
- 适配主流屏幕尺寸（5.0寸-6.8寸）
- 支持竖屏使用（部分页面支持横屏）

### 数据安全

- 用户密码使用 bcrypt 加密存储
- API使用 JWT Token 进行身份认证
- 图片传输使用 HTTPS
- 用户上传内容不进行敏感内容识别（答辩阶段）

### 数据存储

- 用户发布的表情包永久保留（除非主动删除）
- 检索历史保留最近30天
- 斗图室消息不持久化存储
- 单用户表情包上传上限：500张（MVP阶段）
- 初始种子表情包数量：≥1000张

## 17. 总结

本项目从真实聊天场景出发，关注用户「想发表情包但找不到」的高频痛点。与单纯依赖关键词搜索不同，系统将用户的图像化记忆、文字描述和摄像头实时内容作为检索入口，尝试用轻量级多模态检索方式提升表情包查找效率。项目技术路线清晰、功能范围可控、实践周期可执行，既能够完成课程实践的工程实现要求，也便于形成需求、设计、接口、测试和答辩等完整软件工程文档。

> **【本次更新】** 项目升级总结：
>
> 「表情云库」从原项目「多模态表情包检索系统」的基础上，将产品定位从「检索工具」升级为「表情包众包管理与社交分享平台」。
>
> **核心升级点：**
>
> 1. **从「单向检索」到「双向闭环」：** 检索线满足消费需求，创作线满足生产需求，优质创作入库反哺检索，形成数据飞轮。
> 2. **从「工具」到「社区」：** 新增社区广场、排行榜、斗图室、话题挑战、关注体系和悬赏功能，让表情包从工具变成社交载体。
> 3. **AI定位修正：** 不做生成式AI（扩散模型等），聚焦可落地的表情/动作→表情包映射检索，配合CLIP多模态特征提取。
> 4. **差异化明确：** 与微信表情包错位竞争——微信是「私人工具箱」，我们是「开放众包表情库+创作社区」。
> 5. **逻辑闭环清晰：** 检索线（消费已有表情包）和创作线（发布新表情包）两条线分离，社区广场仅展示用户原创内容，优质创作被收录入库后进入检索线，形成健康的内容流转。
>
